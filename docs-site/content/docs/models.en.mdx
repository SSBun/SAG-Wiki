## Model responsibilities

Location: **Settings → Model settings**.

| Configuration | Purpose | Required for |
| --- | --- | --- |
| Answer model (LLM) | Write answers, call tools and summarize search results | Q&A and enabled search summaries |
| Jev model | Judge whether candidate passages provide necessary evidence | SAG2 deep search and CLI semantic search |

Local indexing and quick search need neither model. Jev alone enables semantic retrieval. An answer model alone cannot perform SAG2 retrieval that depends on Jev.

## Configure each field

### Provider

Selecting a provider fills its endpoint. Answer providers include OpenAI, DeepSeek, GLM, OpenRouter, 302.AI and Custom. Jev providers include OpenAI, 302.AI, OpenRouter, Typesafe and Custom.

Answer generation and Jev judging use different APIs. Endpoints are not interchangeable simply because they share a provider. A custom service must support the relevant API.

### Endpoint

Enter the API base URL provided by the service, not its web chat address. Presets fill this automatically. For a proxy or self-hosted service, check its path and protocol.

When switching to a different service origin, supply that provider's API key. The app does not automatically reuse the previous provider's key with the new origin.

Jev accepts a base URL such as `http://127.0.0.1:8000/v1`, or a complete `/systemone` or `/decisions` endpoint. The endpoint suffix is not added twice. For base URLs, the selected decision protocol determines the suffix.

### OpenAI configuration

Select **OpenAI** on the answer card. Use `https://api.openai.com/v1`, enter one available model ID per line and supply an OpenAI API key. Models must support **Chat Completions and tool calling**. Models that only support Responses cannot be used here. The connection check verifies a text reply; check tool calling separately in Q&A.

Select **OpenAI** on the Jev card to set **OpenAI Decisions**, API key authentication and the `gpt-6-luna` model. The official Decisions reference currently lists only this model; access depends on your account. Enter a key in each card. A ChatGPT or Codex subscription login does not replace an API key.

**Decision API protocol** distinguishes two formats:

- **Typesafe Noul** preserves the `state` and `noul` format used by the existing 302.AI, Typesafe and OpenRouter decision integrations.
- **OpenAI Decisions** sends `input` and a `predicate` question array to `/v1/decisions`. The returned `probability` becomes the passage relevance score. A proxy must implement this same protocol.

The scores can have different calibration. After switching, check retrieval with known questions and relevant passages. A probability does not guarantee correctness, and existing Noul thresholds may not have the same effect. Refusals, mismatched candidate counts or names, and invalid probabilities produce errors instead of zero scores.

![OpenAI Decisions protocol, model and connection settings](/images/product-openai-decisions-en.png)

The selected protocol and model are saved with settings. Existing configurations without a protocol field retain Typesafe Noul. Test the connection, then save settings.

### Jev authentication

- **API Key**: use for services that require a key. Existing configurations retain this default.
- **No authentication**: use for local Jev services that do not require a key. No authorization header is sent, and saving removes the previously stored Jev key.

The service must implement the Jev judging API. For the CLI, use `sag config --url http://127.0.0.1:8000/v1 --model YOUR_MODEL --auth none`. Switch back to a keyed service with `--auth bearer --key-stdin`.

### Available models and model name

**Available models · one per line** controls the answer models shown in the UI. Enter an exact supported model ID on each line, without commas. Duplicates are removed on save. The connection check uses the model and effort selected in **Model for reasoning settings** below.

For Jev, enter one model ID in **Model name**. The current default is `jev-latest`; verify availability with your provider.

### Reasoning effort

On the answer card, select an available model in **Model for reasoning settings**, then open **Reasoning effort**. This shares the saved per-model setting with Chat settings and the chat composer. Save changes to apply them. Selecting a model for configuration does not change the model used by the current conversation.

For `gpt-6.1-sol` at the official OpenAI URL, `https://api.openai.com/v1`, the options are **Default, Low, Medium, High and Very high**. Default omits the parameter; the other options send `reasoning_effort` as `low`, `medium`, `high` and `xhigh`. Default uses the service default and does not disable reasoning. Live requests on 2026-11-11 verified these four explicit values. Although the model page lists `max`, the Chat Completions endpoint rejected that value, so it is not offered.

Other models and proxy URLs show only mapped levels. Unknown model/service combinations retain Default. A model name does not establish a proxy's parameter support. This option does not apply to Jev or Decisions.

Official tool calling for `gpt-6.1-sol` requires the Responses API. This app currently uses Chat Completions for chat. Reasoning levels work for text generation, but this change does not add SAG or MCP tool calling for that model.

### API key

Enter the key for the selected service. The field is hidden by default; use Show or Hide to inspect it. Leaving a saved field blank preserves its key. **Remove saved key** deletes that key immediately.

When both providers are 302.AI, entering a key can fill the other unconfigured field automatically. Review both configurations before saving.

### Test connection

Use **Test connection** on each card to verify the endpoint, model and key. Then select **Save settings**. Tests may send validation requests and incur provider charges.

![Separate Jev configuration and connection test](/images/product-jev-en.png)

## Setup sequence

1. Configure Jev, test it, save and run a deep search.
2. Configure and test an answer model that supports tool calling.
3. Save, select that model in Q&A and ask a question with verifiable sources.
4. Adjust prompts, reasoning or tool permissions under [Q&A settings](/en/docs/chat#qa-settings-in-detail).

## Connection problems

- Authentication failure: check the provider, key and expiry.
- Unknown model: verify the exact ID and account access.
- Invalid endpoint: check the API URL and required path.
- Timeout: check the network and provider status; Q&A request timeouts are adjusted in Q&A settings.
- No tool calls: verify that the model and API support tools, then check that model's bindings.

Keys are stored in the current user's application data directory. macOS uses owner-only file permissions; other processes running as that user may still read them. Do not publicly share the data directory. See [Data and privacy](/en/docs/privacy).

## MinerU document parsing

Open **Settings → Model settings → Document parsing · MinerU**. It is disabled by default. Choose 302.AI (the default) or MinerU official and enter that provider's API key/token. The endpoint is selected automatically.

When enabled, supported PDFs, images and Office documents use MinerU first, then the applicable built-in anydoc parser and installed local Docling on failure. Markdown, text and code remain directly indexed. The app does not switch cloud providers or install components automatically.

![MinerU provider, key and connection test](/images/product-mineru-en.png)

**Test connection** uses the current unsaved settings without uploading files or creating a parsing task. Reachability does not prove that a key is valid; the result distinguishes them. Keys are stored separately for each provider. Save settings, then reindex failed files.

Advanced settings control request timeout, task deadline, polling interval, concurrency, parsing model, OCR, table and formula recognition. PDFs are split to meet provider page and upload limits; only complete results are published, retaining original page numbers. Stored task identifiers allow polling to resume after a timeout. A submission without a returned identifier remains uncertain and falls back locally to avoid blindly submitting it again.

Remote parsing uploads the original document; see [Data and privacy](/en/docs/privacy). Index history shows each engine, phase, duration and failure.

## Advanced runtime settings

Model settings also provides retry count, backoff intervals and a total request deadline. HTTP 499 counts as a retry; the deadline covers requests, delays and reading responses. See [Runtime settings](/en/docs/preferences#runtime-settings) for the other groups.
